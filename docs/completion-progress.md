## A: controller and IPC regression passed

- IPC version 4 separates acceptance from serialized controller execution. Mutations require the current host session. Results are queried using `operation-status` with the operation ID and original host session.
- Operation states: queued, running, completed, failed and cancelled. Completed records expire after ten minutes, with 256-record and 32-MiB limits. Queued/running work is never expired; admission also bounds pending work.
- The WinUI FIFO transport reconciles pending IDs after timeout/reconnection and never replays a mutation. Late errors are surfaced when a snapshot refreshes the UI.
- Device selection, channel configuration, persistence preferences, policy and recovery live in `DeviceController`. The controller accepts a simulated device manager, preferences and clock. The previous 15-second manual-selection grace period has been removed in favor of explicit generations. Generation checks also reject a driver completion superseded during a reentrant configuration change.
- Eleven suites passed before B. Temporary host integration passed, including acceptance of quit before shutdown: `out/test-profiles/integration-f553001af71948399e0e8c95c5dc4c94/integration-result.json`. A second pass after the instance changes is in `out/test-profiles/integration-38eb5fb867ee491fb319a86e707f8298/integration-result.json`.

## B: controller and offline processing regression passed

- `PluginInstances` is an ordered record collection with independent UUIDs, original class identity, original/legacy descriptions, state, bypass, custom-name storage and loading condition. The active chain no longer uses `KnownPluginList` or synthetic vendor UIDs.
- The transitional `pluginInstancesV1` adapter preserves the old keys/XML. Migration backs up the original preferences first, reads exact legacy keys before normalization, and retains ambiguous/corrupt material. Unsupported or malformed adapter data disables overwriting. The adapter is retained as a migration source; stage F now owns session writes.
- Installed commands now resolve stable class IDs on the controller; asynchronous scans cannot retarget queued index actions. UUID actions and duplicate states survive restart in the real no-audio host integration: `out/test-profiles/instances-91982273344c42b180b511c480ad4654/instance-result.json`.
- The callback loads a lock-free atomic raw snapshot pointer. Shared ownership and destruction remain on the controller, behind callback admission/drain coordination.
- `DryDelay` allocates for the actual host channels, retains recent history across latency changes and crossfades compatible taps over 5 ms. Plugins keep their original bus layout; unconnected auxiliary inputs receive silence and auxiliary outputs do not enter the main serial route.
- `HostAudioPlayer` prepares channel views and storage outside the device callback and segments large driver blocks. Host MIDI admission is explicitly limited to 1 MiB, preserves complete events and counts discarded events.
- A read-only capacity accessor is applied reproducibly to the build-owned JUCE copy by `Utilities/PatchJuce.cmake`. This makes host MIDI admission safe even if a plugin shrinks the supplied buffer; depleted storage is repaired by the controller. Local JUCE checkouts are copied before adaptation.
- The Release test intercepts this executable's C allocation imports and C++ new/delete, and labels host versus simulated-plugin processing scopes. The channel matrix, asymmetric buses, latency-history, plugin-generated MIDI and plugin buffer-shrink cases passed with zero host allocations/frees. The rebuilt regression passed, including the subsequent channel-major dry-history optimization. These measurements do not assert that third-party DLL internals allocate nothing.

## C: scanner and paginated failure regression passed

- Filesystem enumeration and fingerprinting moved to the Job Object-owned scanner, with immutable candidate batches, per-root deadlines and continuation after a blocked root. Canonicalization deduplicates overlaps without changing JUCE's original identifier.
- Scanner/cache protocol 2 verifies each class by instantiation, keeps valid sibling classes after a failure, and stores declared/verified bus metadata. Relevant content changes invalidate the cache even when size and timestamp are unchanged.
- Failure IDs, revision-bound pages of up to 100, full details and selected/all retries are implemented. Three actual UI scenarios passed with 151 failures in `out/ui-scanner/results.json`: complete details, selection retained across pages, selected-ID retry and retry-all preservation of the bank/chain.
- Twelve Release CTests passed in 9.91 seconds after C, including actual junction/extended long-path fixtures, simulated filesystem hangs/access denial, crash/cancel, cache mutation, partial class failure and all 151 failures across pages.
- Real Dragonfly discovery, class/bus verification and restored cache passed for four VST2 and four VST3 modules: `out/real-plugin-test/scan-results.json`. Processing, state and editor verification followed during integrated testing; its separate results are recorded below.
- Real host IPC pagination, selected retry and stale revision rejection passed in an isolated no-audio profile: `out/test-profiles/scan-d70752caab3b45eda702e635c586ba21/scan-result.json`.
