# Canvas controls, settings and release notifications

| Before | After | Why |
| --- | --- | --- |
| Cards and corner overlays exposed content behind them | Opaque light/dark theme surfaces; dimmed inner content for bypass | Keep overlapping cards readable |
| Keyboard search stopped at the first preview | Arrow keys preview successive nodes without leaving the search | Navigate results continuously |
| Channel menus listed single ports in Pairs mode | Pair labels and atomic pair enable/disable actions | Match the Audio page |
| Smaller spacing limits applied only on the next drag | Existing layouts are constrained after changing the slider | Apply the setting immediately |
| Canvas context toggles reserved a checkmark gutter | Action labels describe the next operation | Keep menus aligned |
| Animation lived in the context menu | Animation and arrows share a separate bottom-right card | Group view controls consistently |
| Hidden notices reserved page space | Closed notices collapse; Audio selection controls center their content | Align page content and form fields |
| Destructive actions were always exposed | Danger zone is collapsed behind a toggle, followed by About | Reduce accidental exposure |
| Updates only appeared in Settings | Optional in-app release notification opens Settings | Make new stable releases discoverable |

The release notice is enabled by default, checked at startup and every six hours
while the interface exists, and remembered per version. A hidden/minimized window
defers displaying it until opened. Downloads and installation remain manual.
The existing stable-release/version validation and updater are reused.

Validation used scripted UI Automation and screenshots in disposable profiles.
Keyboard search retained focus across multiple results; paired channel actions
changed both masks together; reducing distance moved a distant card without a
drag, while the canvas page was hidden. Dashboard and Audio content tops matched
exactly. Danger zone reveal/hide and List-mode setting visibility passed.
The notification was exercised with local release metadata, including its
Settings action, a second release and persisted opt-out; no download/install.

Release WinUI compilation and portable startup passed. Native audio code was
unchanged in this review. The complete test suite and real audio/plugin checks
were not run. Screenshots: `out/ui-review/revision5.html`.
The final extracted portable is `dev-test/LightHostModern-build-0016` (0015 was
superseded during the final light-theme separator review). No remote operations.
