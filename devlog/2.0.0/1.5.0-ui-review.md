# Chain and profiles UI review

The first development build exposed inconsistent page insets, crowded controls,
and an unframed canvas. This pass aligns the new UI with the existing WinUI pages.

| Before | After | Why |
| --- | --- | --- |
| Profile toolbar started at the sidebar edge | Shared responsive page insets and a compact toolbar card | Aligns it with the page title and existing List controls |
| Search floated above a separate create button | Search and New profile share one row | Keeps profile navigation and creation together |
| Profile cards repeated four large buttons | Activation plus labeled icon actions, readable metadata and tooltips | Reduces clutter and prevents long names from displacing actions |
| Canvas commands floated to the right | Primary add actions on the left; view/history commands on the right | Makes the entry point and supporting actions clear |
| Canvas blended into the page | Framed canvas, short gesture hint and live zoom percentage | Separates editing space from application controls |
| Small port labels and crowded mixer controls | Larger sockets, aligned input/output columns, flexible sliders and compact mute buttons | Improves legibility without changing the channel model |
| Card options were only discoverable by right-click | A menu button on each card opens the same actions | Makes channel visibility and other actions discoverable and accessible |
| Fit used a fixed height for every card | Fit and Organize use rendered card heights | Accommodates mixer cards and multi-channel plugins |
| Bright cyan wires in the light theme | Theme resource brushes for wires, sockets and activity dots | Preserves contrast when the application theme changes |
| Settings used separate text/toggle styles | Existing subtitle, card, blue-link and compact-toggle styles | Matches the rest of Settings |
| Plugin picker listed only names | Name, format/vendor, search and an explanatory empty state | Makes similarly named installed plugins easier to identify |

Screenshots were captured through PowerShell UI Automation after
the user requested scripted navigation. Review instances use isolated profiles;
populated visual scenarios use sample metadata and a mock IPC host, without
loading plugin binaries or opening audio devices. Final captures activate the
review window and capture its screen bounds so native menu popups are included.
Screenshots are in
`out/ui-review/before` and `out/ui-review/after`.

The reusable `Utilities/Capture UI Review.ps1` navigates an already-running test
profile and saves PNGs with visible control information. It does not run the
automated test suite. Use `-UiPid <WinUI process ID> -AllPages`, or `-Page Plugins`
with `-Invoke <automation ID or accessible name>` for individual states.
Use `-IncludeNativeMenus` for foreground screenshots that include native popups.

Coverage includes List/Chain headers, profile selection and forms, create/edit/
duplicate/delete confirmations, plugin picker, canvas cards and mixer, Settings,
Appearance, both themes, English/Portuguese, long names and a smaller window with
the sidebar expanded. Runtime audio validation remains outside this visual pass.

Development build **0005** was packaged with a verified UI binary hash. The actual
portable was opened in separate List and Chain review profiles with `--no-audio`,
and its Plugins, Profiles and Settings pages were captured. No test suite was run
and no remote repository changes were made. The screenshot gallery is available
at `out/ui-review/index.html`.
