## Implementation and recovery

Portable staging rejects unsafe Windows paths and reparse points, restricts files to release payload locations, verifies the package checksum/version/architecture, and preserves unrelated user files. Each replaced file has a backup; detected failures roll back in reverse order. Failure retains the journal and backup directory. This does not guarantee atomic recovery from power loss or forced updater termination; see `docs/update-contract.md`.

The operation helper runs outside the app directory and waits for the exact host/UI process instances. The Windows Installer path remains disabled for isolated profiles. No release was installed on the user's normal app or published remotely.
