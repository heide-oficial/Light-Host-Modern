# Chain, search and audio presentation review

| Before | After | Why |
| --- | --- | --- |
| An unused toolbar row reserved spacing below the controls | Spacing is reserved only when commands wrap | Center search and commands in the card |
| Nested combo items consumed suggestion clicks and inherited transparent hover colors | Passive suggestion content uses the native selectable container and local hover colors | Support mouse selection, feedback and dismissal outside the search |
| Card dragging changed both dimensions with an arbitrary width cap | Width-only resizing stops at the measured channel content limit | Avoid empty height and excessive width |
| Bypass used a warning-colored border | Dimmed cards use diagonal stripes; global bypass applies to every card | Distinguish bypass from errors |
| Device aliases were edited inline | A pencil opens the rename dialog, then returns to the device manager | Match channel renaming while preserving unsaved selections |
| Hardware channel visibility was independent of Audio | Hardware channel menu updates Audio enablement; grouping and mono are shared | Keep both views consistent |
| Individual channel aliases were absent from pairs | A shared name formatter composes the individual names in both views | Preserve custom names across presentation modes |
| The Chain plugin picker was a small plain list | A wider catalogue supports manufacturer grouping, sorting and scan access | Make installed plugins easier to find |

The canvas subtitle identifies the element type; runtime status remains available
in its tooltip and visual treatment. Muted output dims its hardware card. Idle
wires use reduced opacity, and fresh audio levels activate their accent color.
List mode reflects global bypass and offers “Disable bypass chain”.

Profiles use the normal button height and identify the default as a built-in clean
profile. Dashboard includes the current operating mode before Active plugins.
Every Chain context menu, including nested menus, receives action icons.

Validation uses scripted UI input/captures and disposable profiles. No remote
repository operations are part of this change.

Focused checks passed for mouse suggestion selection and outside dismissal in
both modes, modal device renaming, width-only resizing and its content bound,
composed pair aliases in Audio/Chain, shared mono, and disabling global bypass
from List. Captures cover the toolbar, grouped picker, bypass/mute, device manager
and Dashboard. Native validation checks wide-card persistence and normalization
of old hardware-only visibility masks. Full audio/plugin compatibility testing
and the complete test suite are not part of this UI review.

Delivered in `dev-test/LightHostModern-build-0013`. Release host and WinUI builds
completed, both packaged executable hashes match, and the portable opened in a
fresh isolated profile with the built-in default. Review gallery:
`out/ui-review/revision3.html`.
