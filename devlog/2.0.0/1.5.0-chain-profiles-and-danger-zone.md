# Chain interactions, profile actions and reset controls

| Before | After | Why |
| --- | --- | --- |
| Native port buttons consumed drag events | A dedicated pointer surface captures a connection from either endpoint | Wires can be created with a normal drag, including input-to-output |
| Mixed button treatments and overflow in the Chain toolbar | Consistent commands, responsive rows, history controls inside the canvas | Keep actions visible and aligned |
| List labels sat above their icons and against the separator | Adjusted label bounds and separator margins | Align text and give actions breathing room |
| Profile actions occupied each card | A three-dot menu contains Activate, Overwrite, Edit, Duplicate and Delete | Keep cards readable without repeating action buttons |
| A profile could be absent after deleting or changing modes | Empty protected defaults exist for both modes | Always retain a valid profile identity |
| Audio channel grouping and Chain grouping differed | Hardware ports read the same per-device UI preferences | Individual/Pairs looks the same in Audio and Chain |
| Cards had a fixed shape | Persistent resize dimensions and horizontal wrapping channel layout | Accommodate different channel counts and labels |
| Destructive actions had inconsistent safeguards | A Danger zone uses confirmation with a three-second lockout | Prevent accidental acceptance |

The device manager edits display aliases without changing driver/device identities.
Audio selectors and dashboard captions use these aliases. Name restoration covers
the catalogue, current session, saved profile contents, devices and channel aliases.
Profile names remain user-defined metadata. The default profiles cannot be edited,
overwritten or deleted; duplicate them or save the current setup as a new profile.

Overwriting preserves the target profile's name, description, creation date and
audio-capture preference. It captures the current setup without activating a
different profile. Deleting the active profile activates its mode's empty default;
deleting all profiles restores both defaults and stops the current plugin chain.

Factory reset uses an app-owned marker processed on the next startup after both
processes stop writing. It clears the exact preferences/session/profile/UI files,
resets capture state and Windows startup registration, and prevents old preference
migration from reintroducing removed settings. Plugin binaries and exported logs
are retained. No directory-wide removal is used.

Focused checks use isolated test profiles with audio disabled. They cover protected
defaults, overwrite and activation, card view persistence, restoring names in saved
profiles, delete-all and factory reset. Scripted UI checks cover gestures and visual
layout. These checks do not replace real audio/device/plugin compatibility testing.
