# Visual preferences, popup stability and Windows release notifications

| Before | After | Why |
| --- | --- | --- |
| Popup content was reparented and themed after opening | Prepare closed dropdown/suggestion templates before input opens them | Preserve keyboard focus and pointer selection |
| Caption buttons painted an opaque rectangle | Transparent normal/inactive caption backgrounds with themed hover states | Let the selected window material continue behind the buttons |
| Sidebar visibility option followed Sidebar on open | Option follows App icon | Requested settings order |
| Successful-action notifications could not be hidden | General > Action notifications, enabled by default | Control lower-right confirmations without hiding hover hints, errors or updates |
| Scrolled content ended at a hard edge | Optional composition fade at overflowing top/bottom edges | Soften clipping without moving controls |
| Decorative work always ran | Performance mode uses solid surfaces, disables fades and wire animation, and lowers UI refresh frequency | Reduce visual overhead while retaining audio and useful status information |
| Update preview was exposed as a temporary setting | Preview removed; native Windows release notification added | Notify outside the app without a development-only control |

Performance mode retains the user's material, fade and chain-animation settings.
Turning it off restores them. It does not change routing, plugins, the audio
callback, or saved profiles. Hover tooltips remain enabled, as clarified by the
user; only brief successful-action notifications use the new preference.

Dropdown preparation never detaches focused popup content. Open popups are not
rethemed by the polling pass. Context menus retain their native presenter
backdrops. Windows caption buttons retain native interactions and close hover.

The fade uses a CompositionVisualSurface and opacity mask on the existing scroll
viewport, with updates on scroll and size events. It does not take screenshots,
run a frame timer, or intercept pointer/keyboard input. High contrast and
Performance mode release the mask and restore the original visual.

Windows notifications use the host's existing tray icon. The IPC command validates
a newer version and the persisted opt-out setting; successful submissions are
remembered separately from in-app notices. Clicking the native notification opens
the app. The OS controls banner presentation (including Do not disturb).

References: [WinUI title bars](https://learn.microsoft.com/en-us/windows/apps/develop/title-bar?tabs=winui3),
[system backdrops](https://learn.microsoft.com/en-us/windows/apps/develop/ui/system-backdrops),
[WinUI Gallery opacity masks](https://raw.githubusercontent.com/microsoft/WinUI-Gallery/main/WinUIGallery/Controls/OpacityMaskView.xaml.cs).

Validation: Release builds of WinUI and the native host passed. Scripted UI
checks in an isolated profile covered all four material selections without
premature dismissal, repeated audio grouping dropdowns, keyboard suggestion
navigation, context menus, fade on/off, caption appearance, option order,
Performance mode overrides/restoration, and suppressed action confirmations.
Screenshots of the dark UI and the final light portable were reviewed. Some
mouse-search automation runs lost foreground focus to Explorer and were not
counted as passes; live mouse selection still merits manual review.

Native isolated checks passed for stale/invalid release rejection, persisted
notification deduplication, and opt-out. Actual Windows banner display was
intentionally suppressed in the test profile and was not visually verified.

The extracted portable is `dev-test/LightHostModern-build-0018`. Its host and UI
opened successfully with a clean built-in profile. Saved performance/notification
preferences loaded correctly, and leaving Performance mode restored the saved
material/fade options. Packaged WinUI SHA-256 matches the canonical build:
`9C7A0842F1ABCC33B492686F4AC23FB173D3F5EF7D8644BACAFE14D71A29CDED`.

No full regression suite or live audio/plugin validation was run. No remote
operations. Screenshots are indexed at `out/ui-review/revision7.html`.
