# Notification categories and mixer channel labels

| Before | After | Why |
| --- | --- | --- |
| Action and combined release switches were in General | Four independent switches in Notifications | Control actions, warnings/errors, in-app releases and Windows releases separately |
| In-app release dismissal persisted across launches | Dismissal lasts only for the current UI session | Remind users of an available release after reopening |
| Wire animation used play/pause | Static flow icon with a visual-effect tooltip and toggle highlight | Avoid suggesting that audio is being paused |
| Mixer ports had numeric/generic labels | Left/Right labels in Individual and Pairs, with L/R gain labels | Make stereo routing and linked gain behavior explicit |

Existing action preferences are retained. Both new release preferences initially
inherit the old combined setting; the Windows host independently checks its own
new setting. Error/warning suppression only affects transient notifications,
not confirmation dialogs or persistent status information. Hover hints are unchanged.

Mixer labels are presentation-only. The mixer still sums four stereo inputs into
one stereo output. Volume and mute stay linked per stereo input; no DSP changes.
Aliases take precedence over generated Left/Right labels in both presentations.

Validation: WinUI and native Release builds passed. An isolated local update
fixture verified independent notification channels, opt-out, and repetition of
the in-app notice after reopening despite an old persisted last-notified version.
Windows submissions were recorded without displaying a fake OS notification.

Scripted captures verified the Notifications section, the flow toggle in both
states, stereo-pair mixer labels and separate Left/Right ports. The final
extracted portable is `dev-test/LightHostModern-build-0019`; its host and UI opened
successfully with a clean built-in profile. Packaged WinUI matches the canonical
build (SHA-256: `dacd59803dba852e24d804799f2e338ea9ddc91ddc475b5daab97eed72a44aea`). Screenshots: `out/ui-review/revision8.html`.
No full regression suite or live audio/plugin validation was run. No remote changes.
