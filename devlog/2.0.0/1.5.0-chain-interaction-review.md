# Chain interaction revision

| Before | After | Why |
| --- | --- | --- |
| Dragging cards and the background used the same mouse button | Right-drag pans; left-drag selects or moves cards | Keeps selection, card movement and viewport movement separate |
| Host refresh could replace the current camera | Preserve the local camera within a profile and serialize canvas writes | Prevents stale refreshes from undoing a gesture |
| Commands could be skipped during a snapshot read | Routing commands wait for the current operation | Keeps completed gestures from disappearing |
| Organize placed unconnected cards in the hardware column | Topological columns, a separate processing column, and hardware output last | Makes the audio flow readable from left to right |
| Plugin cards repeated editor and bypass buttons | Actions stay in the card menu; double-click opens the editor | Gives the channels more room |
| Every hardware channel was displayed | Only the physical channels enabled in Audio are shown | Matches the current audio setup without renumbering channels |
| Cards looked identical when bypassed or disconnected | Distinct outlines, opacity and status labels; sustained input without output is flagged | Communicates state without relying only on wire animation |
| Canvas painted an opaque background | Canvas and cards use the application's translucent card resources | Follows the selected window material |
| Solid material could use the system's dark background with the app's light theme | Resolve the solid background through the window's theme resource | Keeps the window and canvas readable when app and system themes differ |
| Plugins had a profile toolbar and a canvas toolbar | One toolbar with element search and canvas commands | Reduces clutter; profile activation belongs to Profiles |
| Profiles showed both operating modes | Only profiles for the running mode, with Save changes on the current profile | Keeps the available actions relevant |
| Audio profile option was a loose checkbox | A setting card labeled Save current audio settings | Explains that saving captures the current audio configuration |
| Compact layout always constrained Chain | Appearance can always expand the Chain page | Lets the canvas use the available window width |

Selection supports rectangle selection, Ctrl/Shift additive selection, moving a
group, disconnecting incoming/outgoing/all connections, bypassing/enabling plugins,
and deleting selected processing elements. Hardware input/output cards are retained.
Search locates existing canvas elements and keeps a highlight until that element
is clicked. Adding plugins and mixers remains in the canvas context menu.

Visual and gesture review uses scripted navigation with an isolated mock host;
it does not load plugin binaries or open audio devices. Full audio/runtime test
suites are outside this iteration.

Release compilation completed for the native host and WinUI. Scripted checks
confirmed independent card dragging, stable pan/zoom after saving, horizontal
organization, rectangle selection, group movement, group bypass/enable and input
disconnection. The silent-output indication was exercised with simulated meters.
Light/dark screenshots, Solid/Mica/Mica Alt/Acrylic, the profile dialog, filtered
profiles and the Compact layout override were reviewed. The final extracted
portable is `dev-test/LightHostModern-build-0007`; its interface was opened with
an isolated profile and audio disabled. Screenshots are collected in
`out/ui-review/revision.html`.
