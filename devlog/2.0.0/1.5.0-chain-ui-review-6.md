# Surface materials, card layers and action feedback

| Before | After | Why |
| --- | --- | --- |
| Canvas cards had a fixed solid fill | Bounded system backdrops follow the selected material | Match Mica, Mica Alt, Acrylic and Solid across surfaces |
| Dialogs and dropdowns used unrelated native defaults | Shared surface policy applies to popup templates | Keep settings and transient UI consistent |
| Overlapping cards had no layer controls | Front/forward/backward/back actions, including selections | Control visibility without changing audio routing |
| Danger zone reveal had only a title | Description explains cleanup/reset scope and confirmation | Clarify the consequence before exposing actions |
| Window material was separated from Theme | Material follows Theme | Keep related preferences together |
| Sidebar button could not be hidden | Persisted hide preference below Sidebar on open | Support a fixed sidebar preference |
| Feedback differed between List and Chain | Successful actions share concise notifications | Confirm important changes without channel/viewport noise |
| Update notification needed a new release to test | Temporary, explicitly labelled preview button | Review its appearance without downloads or version-state changes |

Layer order is serialized per node, participates in undo/redo and profiles, and
is excluded from audio-routing comparison. Existing graphs default to layer zero.
The surface policy uses Windows App SDK SystemBackdropElement for bounded
surfaces and native backdrop properties for menu presenters/tooltips. It retains
theme-aware solid backgrounds for Solid mode and high contrast.

API reference: [System backdrops](https://learn.microsoft.com/en-us/windows/apps/develop/ui/system-backdrops).

Validation: Release builds of WinUI and the native host passed. Scripted checks
in disposable profiles covered all four materials, dialog/dropdown/menu captures,
layer actions, successful mute/unmute feedback, update preview, and sidebar
visibility after reopening. Light-theme and Portuguese notification captures
were also reviewed. Native checks covered layer persistence across restarts and
profiles, undo/redo without rebuilding audio, invalid layer rejection, and older
graphs with no layer property. Previewing an update leaves stored preferences
unchanged.

The final extracted portable is `dev-test/LightHostModern-build-0017`; startup of
the packaged host and UI passed with a clean isolated profile. Full regression
suites and live audio/plugin checks were not run. Screenshots are indexed at
`out/ui-review/revision6.html`. No remote operations.
