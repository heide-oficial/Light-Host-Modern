# Chain navigation, resizing and installed catalogue review

| Before | After | Why |
| --- | --- | --- |
| Thumb and viewport competed to resize cards | The grip starts one viewport-owned pointer gesture | Keep width changes stable across consecutive drags |
| Disconnect all duplicated directional actions; empty actions stayed enabled | Only directional actions, enabled from the actual selected edges | Make the scope clear and avoid ineffective actions |
| Channels filled the first submenu | Channels has its own nested group | Keep grouping and mono options easy to reach |
| Add plugin recreated only part of Installed | The dialog hosts PluginsPageView and PluginPageController | Share cards, tree lines, sorting and action presentation |
| A 20% minimum zoom could not fit distant items | Zoom to 0.1%, automatic fit on entry, frame icon and edge indicators | Recover and navigate large layouts |
| Individual drags could leave elements far from the chain | A configurable gap brings distant drops back toward the nearest element | Preserve grouping and wires without losing the card |
| Bypass stripes stopped at the content padding | Stripes fill the rounded card | Apply the status consistently |
| Device labels had a second extra indentation | 20-unit checkbox and 8-unit label gap | Match the audio backend checkbox |

Top-left counters include plugin instances only, counting global bypass and
plugins with no edges. The indicator switch and distance slider are local UI
preferences. Device controls keep their existing behavior; Danger zone icons
use the same warning glyph throughout.

Verification used scripted Windows UI Automation and pointer input in disposable
profiles. Six consecutive resize drags alternated growth/shrink successfully.
Checks covered disabled disconnect actions, the nested Channels menu, grouped
catalogue presentation and returning from Rename, indicator visibility and its
switch, fit on re-entry, device checkbox spacing and a 600-unit distance bound.
A card at x=45,000 remained visible with the expanded fit range. The native host
accepted and saved 0.1% zoom and rejected values below the minimum.

Release host/WinUI builds completed. The extracted portable is in
`dev-test/LightHostModern-build-0014`; its host and UI executable hashes match the
canonical build outputs. It opened successfully with a fresh built-in profile.
Screenshots: `out/ui-review/revision4.html`. The complete test suite and real audio
or plugin compatibility tests were not run. No remote repository operations.
