# Chain toolbar, navigation and names

| Before | After | Why |
| --- | --- | --- |
| Pan and zoom submitted the full graph and showed Saving session | Camera preferences are saved locally, separately from chain edits | Navigation does not dirty a profile, consume undo history or queue a session write |
| Saving appeared as a line below the page title | A small save indicator exposes the status in a tooltip | Keeps the header height stable |
| Chain commands used an icon-only overflow menu | Commands have icons and text; the toolbar adapts to available width | Makes add, organize, mute and bypass discoverable |
| Zoom tools shared the main toolbar and a footer | Zoom out/in, percentage and Fit to screen sit inside the canvas | Groups viewport controls together |
| Organize ran immediately with a sort icon | A layout icon and confirmation dialog | Protects manually arranged cards |
| Hardware availability was inferred from wires | Device availability and missing chain connections have separate labels | A device can be available without a route |
| Channel names were fixed | Individual channels and stereo pairs have independent names | Allows meaningful names without changing audio mapping |
| Active and inactive profiles were mixed | Active profile and Other Profiles sections | Separates the running setup from saved alternatives |

Hardware channel aliases are stored per backend, device and direction in host
preferences. Audio and Chain use the same aliases. Stereo pairs and individual
channels can be renamed independently; Restore original name clears only that
alias. Configuration-generation checks reject a rename if the device changed
while the dialog was open. Renaming never opens or reconfigures a device.

Processing-card and plugin-port aliases belong to the saved chain. Plugin-card
renames use the existing instance-name mechanism, shared with List and tray.
Aliases preserve physical channel indexes and do not change routing or bus layouts.

Command acknowledgements now apply the snapshot deferred during the operation,
so renamed ports, hidden ports and newly added cards update immediately. Saving
the active profile invokes only its save dialog, without also activating it.

Validation: native and WinUI Release builds completed. Scripted UI checks covered
camera-only navigation without session changes, Organize cancel/confirm, card and
port renames, shared Audio/Chain pair names, profile sections and toolbar alignment.
An isolated native host with audio disabled verified alias round-tripping,
session persistence and rejection of a rename with an obsolete device generation.
The final portable is `dev-test/LightHostModern-build-0010`. Full audio/runtime
suites were not run. Screenshots are collected in `out/ui-review/followup.html`.
